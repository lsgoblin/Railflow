## 2. 新增功能需求

### FR-AI-1 一句话查票

- **触发**：用户在首页查询卡的自然语言输入框中输入一句话（如「明天下午去杭州」）并提交。
- **前置**：用户已选择使用 AI 输入框（普通表单入口始终保留）。
- **主流程**：系统调用 LLM 结构化抽取出发站、到达站、日期 → 三槽位填入查询表单并以高亮提示 → 用户可修改 → 用户确认后执行常规车次查询。
- **异常流**：
  - 解析失败/超时（5 秒）→ toast 提示「没听懂，请手动填写」，表单获得焦点，AI 输入框内容保留可改；
  - 站名不在字典 → 同上，绝不猜测填入；
  - 相对日期以服务端时间为准（对齐业务规则 4）。
- **规则**：AI 仅做表单预填，不得触发查询以外的任何操作；票价、余票一律以数据库查询结果为准。

### 新增用例：自然语言查询车次

| 项目 | 内容 |
| --- | --- |
| 参与者 | 购票用户、访客（查询均无需登录） |
| 目标 | 用一句话代替三步表单填写 |
| 主流程 | 输入 → 解析 → 回填 → 确认 → 查询结果 |
| 扩展流 | 解析失败退回手动表单；解析成功后用户修改任意槽位 |
| 非功能 | 解析 P95 ≤ 3 秒；AI 不可用时查询功能完整可用 |

## 3. 新增非功能需求（随 C1/C2 引入）

| 编号 | 需求 | 对应设计 |
| --- | --- | --- |
| NFR-1 | 高并发下同一车次最后一张票只允许一名用户预订成功 | ADR-003 原子扣减 |
| NFR-2 | 支付/取消/超时/退款的重复操作不得引起重复状态迁移或重复扣退 | 状态机条件更新 |
| NFR-3 | 锁座到期后订单最迟 30 秒内失效并释放席位；支付前亦做惰性校验 | ADR-004 |
| NFR-4 | AI 解析失败、超时、服务不可用时，核心查询/购票流程零影响 | ADR-005 降级 |
| NFR-5 | API Key 等凭据不入库、不入版本库 | 配置管理 |
| NFR-6 | 用户仅能访问本人的乘车人与订单；数据迁移后体验账户保留 | 迁移方案含种子数据 |

## 4. 与 Part I 需求的兼容性说明

- 业务规则 1–10 **无一修改**；AI 功能作为输入手段叠加在「车次查询」规则之上。
- Part I 的「支付和退款均为模拟操作」原则不变：模拟支付的强制成功/失败仍由前端隐藏入口（Alt+点击）触发，便于演示与测试。
- 「访客可查询、预订前登录」的角色边界随 AI 功能一并适用：AI 解析接口对访客开放，交易接口沿用登录要求。
