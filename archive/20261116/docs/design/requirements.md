# RailFlow 基本功能需求

## 用户角色

- 购票用户：管理本人的乘车人和订单，完成购票、取消与退票。
- 管理员：维护演示车次及库存，查看订单与操作记录。
- 访客：查询车次；预订前需要登录。

## 基本功能

| 功能 | 描述 |
| --- | --- |
| 账户访问 | 支持注册、登录和退出，区分普通用户与管理员权限。 |
| 乘车人管理 | 用户新增、修改和删除本人的虚构成人乘车人档案。 |
| 车次查询 | 按出发站、到达站和日期查询直达车次，显示发到时间、票价和余票。 |
| 下单锁座 | 用户确认车次和一名乘车人后，创建待支付订单并暂时占用一个席位；无余票时拒绝预订。 |
| 模拟支付 | 支持成功和失败结果；成功后确认订单，失败时可在原锁座期限内重试。 |
| 订单查询 | 用户查看本人订单的行程、乘车人、金额、状态、截止时间、允许的操作和历史记录。 |
| 取消与超时 | 用户可取消未支付订单；锁座到期后订单自动失效，两种情况都释放席位。 |
| 模拟退票 | 展示退票资格、手续费和退款金额；用户确认后模拟退款，成功时释放席位。 |
| 车次管理 | 管理员维护车次、票价和容量，并开启或关闭车次销售。 |
| 操作记录 | 记录锁座、支付、取消、超时和退票等操作的时间、操作者、状态变化和原因，供只读查询。 |

## 业务规则

1. 每个订单对应一个账户、一个具体日期车次、一名成人乘车人和一个席位，使用一种席别的全程票。
2. 同一账户、乘车人和车次组合不能同时存在多笔待支付或已确认订单。
3. 查询不占用库存；下单成功后才开始锁座。锁座截止时间取“下单后十分钟”和“发车时间”中较早者。
4. 时间判断以服务端为准。达到锁座截止时间后不能支付；发车时及发车后不能新建预订。
5. 总容量等于可用席位、有效锁座和已确认席位之和，余票不能为负。多人争抢最后一个席位时只能有一人预订成功。
6. 支付失败不延长锁座时间。取消或超时只释放一次席位，已确认订单不能按未支付订单取消。
7. 已确认订单只能在发车前三十分钟之前发起退票；恰好到达该截止时刻时不允许退票。手续费为锁定票价的 10%，净退款为票价减手续费，金额保留两位小数。
8. 模拟退款失败时，订单保持已确认状态，席位不释放；重复操作不能导致重复确认、重复退款或重复释放库存。
9. 订单保留下单时的行程、乘车人和票价信息，后续档案变更不修改已有订单。车次产生订单后，只允许调整销售开关，不能修改路线、时间、票价或容量；关闭销售不影响已有订单的支付、取消或退票。
10. 用户只能访问本人的乘车人和订单。管理员不能任意改写支付结果、订单状态或操作历史。

十分钟锁座、固定手续费和退票截止时间均为本项目的简化规则。

## 订单状态

| 状态 | 含义及后续操作 |
| --- | --- |
| 待支付 PENDING | 在截止时间前可以支付或取消；到期后自动失效。 |
| 已确认 CONFIRMED | 模拟支付成功；符合退票条件时可以申请退款。 |
| 已取消 CANCELLED | 用户取消未支付订单，席位已释放。 |
| 已超时 EXPIRED | 未在锁座期限内支付，席位已释放。 |
| 已退款 REFUNDED | 模拟退款成功，席位已释放。 |

支付成功使待支付订单变为已确认；取消或超时使待支付订单结束；退款成功使已确认订单变为已退款。支付或退款失败时保留原状态，后续操作仍需满足相应的截止时间规则。
