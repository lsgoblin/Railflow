# 设计摘要

Part I 完成了需求规格与可运行的前端原型（原生 ES Modules + localStorage），跑通「查询—下单锁座—模拟支付—订单管理」闭环。Part II 把原型升级为三层系统，并新增一项 AI 能力。

## 自 Part I 以来的变化

1. 后端定为 Java 17 + Spring Boot 3，替换环境检查时倾向的 Python（ADR-001）。
2. 数据与状态从前端 localStorage 迁到 MySQL：十分钟锁座、争抢最后一张票、超时失效改由服务端事务保证，不再靠脚本模拟（ADR-002/003/004）。
3. 新增「一句话查票」：输入「明天下午去杭州」，出发站、到达站、日期自动填好，失败退回表单；其余候选 AI 功能已评估待评审（[ai-features.md](ai-features.md)）。
4. 划定 AI 边界：只做查询预填，不接触下单、支付、退票，解析结果须过站名白名单与结构校验（[architecture.md](architecture.md) §7）。

## 当前状态

设计文档与 11 张设计图完成：三视图与 ADR、领域模型与核心时序、REST 接口契约、需求变更日志、UI/UX 与界面截图、未决问题与风险、参考文献与成员贡献。实现留待 Part III，以智能体化开发构建原型与 PoC，重点验证并发扣减与 AI 降级两条决策。
