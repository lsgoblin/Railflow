### 2.2 设计约束

| 约束 | 内容 |
| --- | --- |
| 输出契约 | `{ fromStation, toStation, date }`，JSON Schema 校验，三槽位齐才视为成功 |
| 站名安全 | 出发/到达站必须命中系统站点字典（白名单）；同义词（如「杭」→杭州）在字典内配置 |
| 日期口径 | 「明天/后天/周五」等相对日期以**服务端时间**解析（对应业务规则 4：时间以服务端为准） |
| 时间兜底 | 只给日期；「下午」等模糊时段仅用于查询结果排序提示，不作为过滤条件 |
| 降级 | LLM 超时 / 返回不合法 / 余额不足 → 一律回退表单，主流程零影响 |
| 密钥 | API Key 走环境变量，不入库、不入 Git |
| 鉴权 | AI 解析接口与普通接口同权限要求；解析本身不返回业务数据（票价/余票仍走查询接口） |

### 2.3 责任边界（对架构 §7 的重申）

AI 相当于「一个只有一只手的助理」：它能帮你把表单填好，但提交键永远在你手里。解析结果只是**预填建议**，提交查询前用户可任意修改；AI 不接订单、支付、退票任何写接口。

## 3. 为什么不建议做「全站自由对话客服」

1. **幻觉即错误承诺**：班次、票价、退票规则是业务事实，LLM 编造一条「这趟车还有票」就是业务事故；本项目手续费、截止时间均为硬规则（R3–R8），不适合生成式回答。
2. **越权风险**：自由对话天然诱导模型回答「我的订单」类问题，要么绑定查询越权，要么答案无据（见评估表第 4 行风险）。
3. **投入产出**：课程项目时间有限，护栏做到可信的代价远超演示收益；同一预算投入 P0/P1 能得到确定的效果。

## 4. 对 Part III（原型验证）的交接

需要 PoC 检验的 AI 相关点：

- 解析准确率样本集（收集 20–30 条真实说法，含同义词、错别字、口语日期）；
- LLM 超时与不可用时的降级路径演练；
- 开发期 mock：缓存典型请求的 LLM 响应，保证无网也能演示。
