# RailFlow

RailFlow 当前聚焦 **AI 铁路行程助手与实际铁路路线规划**：用户可在地图点选城市，也可通过 AI 对话表达“慢摇到哈尔滨”等偏好。系统使用有来源的历史铁路车次、时刻与区间票价组织参考方案，在主页沿实际铁路走向点亮路线，并支持多轮补充与保存个性化输出。

当前需求入口是 [design-spec.md](docs/design/design-spec.md)。不设产品层面的换乘次数上限；每个选定停留节点默认一天，按到达后的下一自然日可出发计算，用户可调整。例如点选“北京 → 南京 → 上海 → 南宁”后匹配历史铁路方案；站点、车次与衔接以所选数据版本为依据。因预算限制，当前不接入真实票务 API，暂不查询、模拟或按余票筛选；历史票价注明来源/版本，缺失显示未知，不自动填模拟价格，也不承诺当前可售。模拟预订保持最简，景点、住宿和市内交通不在当前范围。

AI 可对“想去新疆”先明确建议具体目的城市并点亮可修改预览；继续说“途经郑州”时保留已有条件，更新当前行程、地图和保存结果。必要信息缺失时针对性回复或追问。真实铁路几何是核心验收，直线、道路路线或站点折线不能替代。

默认优先**换乘列车次数最少**的参考可行方案，同站换车也计一次；有可行零换乘方案时沿用默认实际铁路路线。该排序须满足用户明确途经、停留与历史时刻衔接条件，不限制用户可安排的总换乘次数。

地点数据采用“本地城市/铁路车站 + 高德其他地点查询”：城市与所属火车站/高铁站保存在本地，普通地点按需通过高德 API 查询，不建立全量本地地点库。高德结果用于搜索和定位，不直接充当铁路站码、车次或实际铁路轨迹。

铁路数据采用 `wensimehrp/chinese-railway-gtfs` 预生成包及经车次关联的 `shapes.txt`，初测固定 `gtfs-20261116-085531` 多日版本，先测直达、区间裁剪、多城市自然日停留，再追加跨日。行程日期与参考服务日按固定锚点统一偏移，不强制取去年同月同日；每趟车仍核对参考开行日历。历史票价和城市归属需另补，轨迹准确性须实际核验，详见需求 §6.1–6.3、§8.2。

## 开发约束

现有 Java 17 + Spring Boot 3 + MyBatis + MySQL 8、原生 ES Modules、无前端构建步骤的技术约束保留。其他地点查询已指定高德 API；底图 SDK、具体接口及账号配额待细化，本轮未安装依赖或开通服务。

按决策、search（检索）、开发、review 四类职责协作；后续开发须按确认后的需求和契约推进，旧购票任务不直接沿用。任务与状态见 [tasks/](tasks/README.md)，接续材料见 [handoff/](handoff/README.md)。
