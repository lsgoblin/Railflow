当前需求统一写在本目录 [design-spec.md](design-spec.md)：地图依次点选城市形成路线，系统自动匹配车站且允许用户调整，基于历史车次、时刻和区间票价组织参考方案。因预算不接入真实票务 API，余票暂不查询、模拟或参与筛选；历史票价注明来源/版本，缺失标未知。不设换乘次数上限；停留节点默认一天，下一自然日可出发，支持调整。景点、住宿和市内交通不在当前范围；独立票价、城市归属、跨站衔接、架构与接口仍待细化。

AI 与地图共用行程：支持个性化自然语言规划、信息缺失回复、多轮追加途经和保存/恢复输出；区域目的地先建议具体城市并点亮可修改预览。主页必须绘制实际铁路走向，几何不足不能以示意连线替代通过。默认优先换乘列车次数最少，同站换车也计次；历史时刻下有可行零换乘方案时沿用默认实际线路。保存策略和同次数的次级排序等待细化，功能未实现，也不承诺当前开行或可售。

地点基础库仅维护城市及所属铁路客运站，包括火车站/高铁站；其他地点通过高德 API 按需查询，不批量落入本地站点库。地点定位、铁路轨迹和历史票价各有数据依据；底图 SDK 与高德具体接入仍待细化。

铁路时刻/开行日历与关联 shapes 使用指定 GTFS 仓库，初测固定已内存抽查的 `gtfs-20261116-085531` 多日包；少量路线、区间裁剪和固定锚点日期回放见需求 §6.1–6.3、§8.2。数据来源及映射规则已定，本地导入、实际铁路几何/时刻衔接和回放运行尚未验证，GTFS 不含票价。

前端界面规则见本目录 [frontend-spec.md](frontend-spec.md)：以用户地图参考图为依据，定义全屏地图、悬浮搜索与工作面板、城市组线、AI 多轮联动、车次状态、响应式和验收清单；追加图对应的[路线组件](frontend-spec.md#route-component)明确绿色描边主线、浅绿备选、方向箭头与起终/途经标记。完整规则待独立 review；后续前端 v1 的授权范围与开发自测另见 [20261117-01](../../tasks/20261117-tasks.md#20261117-01)，不以局部实现代表完整设计已验收。

界面遵循“能最简就最简”：仅保留必要信息与操作，详细帮助按需查看，外部视觉资源可按需使用；具体规则见前端规范 §3.1、§5.5。
