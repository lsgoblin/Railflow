## 1. 设计未决项

| 问题 | 影响 | 当前处理与所需依据 |
| --- | --- | --- |
| 历史区间/席别票价来源 | 价格与预算解释 | GTFS 主源不含票价，缺失保持未知；需核对独立来源、版本、区间与席别 |
| 城市归属与车站坐标补全 | 自动选站与轨迹定位 | 建立来源化映射，不按站名截字或以城市中心替代车站 |
| 跨站、最小缓冲、零天停留 | 续程可行性 | 不把未核实接驳标为可行；用户确认规则后再定参数 |
| 同次数次级排序及候选搜索窗口 | 推荐稳定性与计算量 | 主排序只确认换乘最少；不擅自添加价格/耗时优先级或固定换乘上限 |
| 席别/人数等必要字段 | 价格与查询条件 | 由能力配置明确，未定义时不暗设默认值 |
| 保存范围、期限与长期偏好 | 身份、恢复与数据生命周期 | 账号属主规则保留；访客/跨设备/保留期和跨行程记忆待确认 |
| 地图 SDK、地点 API 版本及配额 | 投影、命中、费用与可用性 | 高德底图已接入并完成三组样例的走向核对；域名白名单、配额与长期稳定性未验证。外部普通地点 API 仍未接入，不承诺免费无限调用 |
| 源版本保留与更换 | 旧行程恢复 | 保存数据身份及锚点；替换版本需重算，删除策略未定前不承诺永久回放 |
| 教师建议与范围聚焦 | 最终提交与课程一致性 | 已按[需求 §2.1 的分层](requirements-update.md#scope-boundary)给出核心闭环、必要支撑与后续扩展及退出条件；16 项核心于 11-19 通过独立审核与用户验收。完整产品设计保留为后续方向，不作为本轮必交 |

## 2. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| shape 存在但与实际区间不一致 | 地图给出错误旅行依据 | 逐样例核对站序、方向与铁路走向，歧义留空 |
| 服务日、上车日和自然日混淆 | 后续乘车日期错误 | 累计时刻 + 固定日偏移，基准算例覆盖跨日/闰日 |
| 用户节点多、候选扩展爆炸 | 响应失控或内存增长 | 有限计算、预处理索引、取消与可解释未完成；不隐式删节点 |
| AI 编造站点/票价或覆盖手动编辑 | 错误事实与状态冲突 | 允许字段、实体与 Schema 校验，工具事实分离，baseRevision 检查 |
| 保存超时、跨窗口并发 | 重复记录或丢失更新 | 短事务、版本条件、请求唯一身份、结果核对 |
| 数据授权、来源署名或坐标遗漏 | 来源不可追溯、地图偏移 | 固定版本/哈希/署名与原坐标，转换只做一次；许可适用条件落地核对 |
| POI/LLM 配额或网络失效 | 单项功能不可用 | 有界调用、独立错误与手动路径，不清空输入 |
| 原型截图与真实能力混淆 | 评审把夹具当作数据实证 | 所有样例统一说明来源，保留未接入状态，真实验收单列 |

## 3. Part III PoC 与通过判据

以下全部是计划，未写成已执行结果；性能阈值、调用预算与未决业务参数在试验前确认；本表先定义可重复的输入、观测与正确性判据。例外是 P01、P02 已随 2026-11-18/19 的 MVP 实现实际执行，P03 的跨日时刻显示也已取得证据；结论见本节末，原判据保留以便复核，其余仍为待执行计划。

| 编号与要验证的设计 | 方法与观测 | 通过判据 |
| --- | --- | --- |
| P01 固定数据导入 | 固定 GTFS 包、哈希、日历/外键检查；记录有效/缺失记录和导入耗时 | 目标样例的每段可追溯到同版本运行身份；缺数据有显式结果，不把静态检查写为全国覆盖 |
| P02 真实几何与裁剪 | 需求候选 G7179、G531，再追加 T297；核对有效日期、实际区间、轨迹方向和坐标 | 不多画乘坐区间外的线路，不用道路/直线补齐；人工逐段与可靠铁路走向比对，保存证据 |
| P03 日期与回放 | 0/非0偏移、26:06/56:20、跨月年/闰日、日历例外与覆盖边界 | 完整参考/行程时间与手工基准完全一致；自然日停留和恢复锚点不漂移 |
| P04 搜索与换乘 | 小型可穷举基准图比较规划结果；含同站换车、同实例分段、显式途经、长城市序列 | 约束满足时返回换乘主排序正确；预算耗尽标未完成，不作为“无路”；记录 P50/P95/扩展数/内存 |
| P05 多轮与异步 | 追加郑州、删除建议城市、等待时手动改日期；注入迟到/重复/截断结果 | 显式条件保留，补丁只应用一次；旧结果不能覆盖较新 revision；AI/地图/列表一致 |
| P06 AI 护栏 | 非法实体、额外字段、任意 URL/SQL、拒绝、超时及提示注入 | 不执行未知工具，不提交半个修改，不产生编造票价/可售承诺；保留手动输入 |
| P07 保存与属主 | 同/跨窗口保存、A/B 用户访问、身份过期、写成功后响应丢失 | 用户隔离；版本冲突不覆盖；同 requestId 返回原结果，较新草稿仍 dirty |
| P08 UI 与降级 | 桌面多内核、手机实机、IME、键盘、200% 缩放、底图/POI/AI 故障 | 关键动作可达，输入不丢，实际来源署名可见；夹具只证明界面状态 |
| P09 历史价格 | 完整/部分未知/不同版本区间与席别样例 | 不用零补价、不用全程价相减；来源可追溯，价格不全不称预算已满足 |

P01 与 P02 的实际结果（2026-11-19）：固定包整包导入并激活，九文件解析与版本追溯可用，重复导入同版本为 NOOP 且不重复生成数据；G7179、G531、T297 三组样例的区间轨迹在真实底图上逐段核对通过，端点距离用 Haversine 独立复算（G7179 首末点 61.1/112.7 m、G531 140.5/42.7 m、T297 17.5/1.0 m），G531 不越出南京南、T297 不越出哈尔滨，形状缺失与边界歧义分别返回 `NO_SHAPE`、`BOUNDARY_AMBIGUOUS` 且不补直线。真实铁路走向的目视核对由用户在本机底图完成。因此 P01/P02 判为通过；P03 的跨日时刻显示已验证（T297 26:06 → 次日 02:06、+1 天），但 D0/R0 偏移、闰日与日历例外仍待执行。P03–P09 随完整产品后置。

每项记录固定输入、设备/软件与数据版本、预期/实际、日志或截图、耗时及未覆盖。失败保留原始现象，再记录修复与回归；独立 review 根据这些证据作结论，不能由实现者改写判据后自我批准。

## 4. 优先级与依赖

先执行 P01–P03，确认目标数据和几何可用，再做 P04 的搜索与 P05/P06 的 AI 联动；没有可靠工具事实时不扩大模型自主权。保存/身份依赖已评审契约和真实服务；设备与界面验证可独立进行。历史交易超卖与退票 PoC 不再是当前规划范围的默认验收。本轮 MVP 已执行 P01 与 P02 并另有跨日显示证据；P03 余下项及 AI、保存相关 PoC 随完整产品后置。
