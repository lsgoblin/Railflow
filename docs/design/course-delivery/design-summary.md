# 设计摘要

李司翰｜2453202｜单人项目｜CD-20261119｜2026-11-19

RailFlow 以地图查票与铁路线路展示为重构切入点：用户选择城市与出行条件，系统组织有来源的历史铁路参考行程，并把对应区间画在实际铁路轨迹与真实底图上。

Part I 与课堂汇报版包含查票、锁座、支付、退票和管理等完整流程。作者转述，教师认为原范围过大、不切实际，建议聚焦系统的一个特色点，例如地图查票。作者据此重构；预算约束进一步促使系统采用固定历史时刻，价格缺失显示未知，不承诺当前开行或可售。地图必须关联实际铁路几何，不能用示意线代替。

新版保留 Java 17、Spring Boot 3、MyBatis、MySQL 8 与原生 ES Modules。单体后端按地点、规划、几何、AI 编排与保存分工。服务日、跨日时刻和行程日期分别建模，停留按自然日计算，推荐优先换乘次数最少。AI 只解释意图，铁路事实由确定性服务核验，多轮修改用同一行程版本防止旧响应覆盖新编辑。

范围于 2026-11-17 收敛为两项主能力：固定 GTFS 包整包导入，与同一车次任意两站区间的真实铁路轨迹叠加真实底图；形成 16 项可验收的 MVP 闭环，AI、票价、保存与换乘后置。11-18 至 11-19 完成实现：整包导入约 478 万行，后端同源托管前端，三组样例车次的区间轨迹在真实底图上逐段核对，16 项 MVP 经独立审核与用户逐项验收通过。跨浏览器/真机与并发压力待验证，产品 AI 仍为设计，见[功能清单](../feature-list.md#mvp)。
