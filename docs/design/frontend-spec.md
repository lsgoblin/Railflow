## 1. 适用范围与依据

本规范定义 RailFlow 的地图工作区、城市路线编辑、AI 对话、铁路方案展示和保存行程的前端规则。用户附图是布局和视觉参考，图中文字、品牌、功能入口不构成本项目的新需求。

本轮 MVP 按[功能清单](feature-list.md#mvp)收敛，实际接口/服务日/坐标责任见 [MVP 契约](mvp-contract.md)：GTFS 起终站、全部直达车次与区间轨迹；允许选包内参考服务日（默认 2026-11-16），后端返回 WGS84，仅高德适配器转换为 GCJ-02。本规范其他完整产品能力不自动进入两日实施范围。

业务依据采用当前 [design-spec.md](design-spec.md)、[README.md](../../README.md) 与当日任务 [15](../../tasks/20261116-tasks.md#20261116-15)、[16](../../tasks/20261116-tasks.md#20261116-16)、[17](../../tasks/20261116-tasks.md#20261116-17) 的确认记录：

- 地图点选城市或铁路站即加入同一有序行程。城市由系统匹配车站，铁路站保留所选站码，用户可调整。
- AI 与地图共享当前行程；支持多轮追加条件、区域目的地建议、缺失信息回复与保存/恢复。
- 用户选择的停留节点默认停留一天，按到达后的下一自然日可出发计算，可调整；不要求满 24 小时。
- 优先列车换乘次数最少的可行方案；同站换车也计次，同一列车途经或分段展示不额外计次。
- 不设产品层面的换乘次数上限；明确的城市顺序、途经、停留及历史时刻衔接条件继续有效。
- 地图沿有来源的实际铁路几何点亮；车次、时刻和历史区间票价注明来源与版本。暂不查询或模拟余票，也不据余票筛选。模拟预订保持最简。

**依据核对记录**：编写初期曾读到综合旅行旧草案；需求维护任务 [20261116-19](../../tasks/20261116-tasks.md#20261116-19) 随后已将 `design-spec.md` 同步为铁路范围，本规范已复读核对。前端设计不恢复景点、酒店、市内交通或旧票务后台，也不修改需求文件或代替业务裁决。

**数据范围更新**：按用户预算决定及任务 [20261116-20](../../tasks/20261116-tasks.md#20261116-20)，当前基于历史时刻和历史票价提供参考规划，不接入真实票务 API。余票暂不处理，不显示有票/无票/已核实可售；历史价格缺失标未知，不补模拟价格。下文仅同步数据表达与验收，既有布局、路线样式及桌面 AI 侧栏规则保留。

本地目录维护城市和铁路客运站。底图使用高德 JS API 2.0，普通地点经后端按需查询高德 Web 服务 v3。地点搜索、预览和铁路关联见[需求 §8.1](design-spec.md#81-本地点位与高德地点查询)。

**GTFS 与日期回放更新**：按任务 [20261116-28](../../tasks/20261116-tasks.md#20261116-28) 与需求 §6.1–6.3、§8.2，初测固定 `gtfs-20261116-085531` 多日包，使用关联 shapes，先验证少量路线。主日期保留用户行程日期，历史回放短标与详情说明参考日期/版本；统一日偏移、服务日和区间裁剪由服务端处理。历史票价另补，布局、配色及任务 22 的交接约定保持。

以下尺寸、颜色、布局和交互反馈是本次提出的前端设计规则。供应商、接口、搜索窗口、跨站衔接、同换乘次数的次级排序、保存版本策略等业务未决项，不由视觉设计自行定稿。

## 3. 设计原则

1. **能最简就最简**：默认只显示完成当前操作必需的信息和控件。页面不放设计理念、技术说明、重复引导和装饰性描述；能删除而不影响操作的元素直接删除。
2. **地图先于面板**：城市、车站和铁路走向是主体，输入与结果围绕地图展开。
3. **一个当前行程**：手动选点、AI 修改、方案选择和恢复行程同步到同一份状态。
4. **层级清楚**：城市、车站和列车区间通过结构与标记区分，避免用长段文字解释层级。
5. **状态简短**：必要状态在对应对象旁出现一次；细节按需展开。
6. **反馈就近**：动作结果与错误出现在触发位置，保留继续操作的入口。

### 3.1 页面文案与信息密度

本节约束后文所有页面文案；后文的设计与业务规则供实现参考，不作为需要逐句展示的界面说明。

- 设计依据、技术实现和规则推导留在文档中，不复制进页面、空状态或 AI 欢迎语。
- 字段标签、按钮名称和内容能表达用途时，不再添加同义副标题、提示段落或“点击此处”说明；同一动作在同一视图只保留一个主要入口。
- 默认展示名称、日期、时刻、金额和必要的短状态。计算口径、完整来源、推荐理由与操作帮助通过详情、折叠项或可点按/键盘打开的提示按需查看。
- 历史参考属性、模拟标记、影响选择的缺失信息与错误保持简短可见；同一结论只提示一次，不铺满页面，不依赖 hover 才能看到。
- AI 默认直接给结果或提出当前需要补充的问题，省略自我介绍、能力宣传和重复复述。长解释只在用户追问或主动展开时提供。
- 不为填充留白添加卡片、图例、统计、插画、徽标或说明文字。留白用于保持地图与操作清楚。

| 场景 | 默认呈现 |
| --- | --- |
| 搜索框 | “搜索城市、车站或地点”，不追加整段搜索教程。 |
| 停留设置 | “停留 1 天”；自然日口径在设置提示中查看。 |
| AI 空会话 | 一个输入框和发送动作，不预置介绍气泡。 |
| 正常路线 | 地图标记与分段信息；需要辨认备选时才提供图例。 |
| 数据版本 | 在方案头部统一标记历史参考版本，完整来源放详情；区间版本不一致时就近标出。 |

## 4. 主页布局与信息架构

### 4.1 桌面端基准

以 1440 × 900 作为布局检查画布，同时覆盖 1280 × 720；这些是设计检查尺寸，不是最低系统分辨率承诺。

```text
┌─────────────────────────────────────────────────────────────────────┐
│ [RailFlow 搜索城市、车站或地点] [全国 ▾] [AI助手 我的行程 保存行程] [账号] │
│ ┌───────────────────────┐                                           │
│ │ 路线  |  AI 助手      │              地图主视区                   │
│ │ 出发日期 / 当前条件   │                                           │
│ │ 北京 → 郑州 → 乌鲁木齐│        城市点、车站与实际铁路走向         │
│ │ 停留 / 车站 / 车次   │                                           │
│ │                       │                                  [全程]  │
│ │ 内部滚动的工作内容    │                                  [ ＋ ]  │
│ │ [查询车次]           │                                  [ － ]  │
│ └───────────────────────┘                                           │
│                                        [数据来源 / 比例尺 / 署名]   │
└─────────────────────────────────────────────────────────────────────┘
```

线框中的城市仅说明信息层级，不代表已经取得历史数据或已验证对应铁路路线。

| 区域 | 尺寸与位置 | 行为 |
| --- | --- | --- |
| 地图画布 | 覆盖整个工作区；高度优先使用动态视口单位并保留普通视口高度回退 | 桌面工作区不产生整页滚动，浮层内容在各自区域滚动。 |
| 搜索栏 | 左上距边 24；宽 360；高 56 | 品牌标识 28–32；输入文字 16；清除与搜索按钮保留可点区域。 |
| 视野入口 | 搜索栏右侧间隔 12；高 48–56，垂直居中 | 宽度随内容，不挤压搜索输入。 |
| 顶部工具组 | 右上距边 24；高 48；按钮间采用留白或细分隔线 | 同一组整体白底，不把每个动作做成大卡片。 |
| 工作面板（展开） | 左距 24；顶距 96；宽 360；底部至少留 48 | 面板头和操作区固定，主体独立滚动；AI 助手栏可收起至视口最左侧。 |
| AI 助手收起入口 | 收起后贴视口最左侧，距左边 0；宽 44、可点高度至少 44，位于搜索栏下方并避开底部署名 | 保留 AI 标识与展开箭头，按钮可读名称为“展开 AI 助手”；点击可恢复侧栏。 |
| 地图工具 | 右距 24；位于顶部工具组下方和底部署名上方 | 单项点按区域至少 44 × 44；组间隔 12。 |
| 状态/图例（按需） | 需要时左下距边 24；避开面板和底图署名 | 默认不常驻说明卡；多方案需要辨认时提供紧凑图例，区间异常就近显示。 |
| 地图来源区 | 按地图服务实际要求置于底边 | 不被按钮、面板或底部抽屉覆盖；不可伪造来源。 |

在 1440 × 900、默认单面板展开时，目标是至少约 60% 的工作区保持为无遮挡地图。打开浮层后，路线适配视野应扣除搜索栏、面板、工具与来源区占用的空间，关键节点不能停在面板后面。

左侧 AI 助手栏支持“展开 / 贴边收起”两态：展开时沿用上述工作面板尺寸，点击面板头部的“收起 AI 助手”后向左收至最侧边，仅保留窄入口，释放原面板占用的地图操作区域。点击贴边入口或顶部“AI 助手”可重新展开，恢复对话记录、输入草稿、滚动位置和当前行程；收起只改变布局，进行中的回复可继续接收。

收起/展开只更新地图控件和路线适配的避让边界，保持当前地图中心与缩放；下次“查看全程”按最新可见区域适配。收起后焦点移至贴边入口，隐藏内容退出键盘导航；入口支持键盘激活并表达展开状态。过渡沿用 §11 的面板动效及减少动态效果规则。

### 4.2 面板组织

- 左侧只有一个主要工作面板，以“路线 / AI 助手”切换内容；顶部“AI 助手”打开同一个面板并选中对应页签，不再打开右侧第二个常驻聊天栏。
- AI 助手显示在该共用面板内时，支持 §4.1 的贴边收起；重新展开复用原面板和会话，不新建第二个聊天窗口。
- “路线”内从上到下为：当前行程摘要 → 日期与条件 → 城市节点 → 分段车次方案 → 查询操作。保存入口统一放在顶部，详情按需展开。
- AI 页签保留同一行程摘要；聊天记录独立滚动，输入区固定在面板底部。切换页签保留输入草稿、滚动位置和已选区间。
- “我的行程”复用工作面板显示列表；选中后进入当前工作区。当前修改未保存时，先提供“保存后打开 / 放弃修改并打开 / 继续编辑”，不静默覆盖。
- 普通车站说明与线路详情用锚定浮层或面板内详情。模态对话框仅用于需要用户做明确选择的中断性动作，如处理未保存修改。

### 4.3 账号、登录与身份恢复

账号入口始终在顶栏；未登录显示“登录”，已登录显示头像或账号短名。首次身份检查期间入口显示轻量加载态，不先闪现其他人的缓存。点击登录打开同页对话框：桌面宽 360、最大宽度为可用宽度减 24，移动端使用同一表单并适配软键盘。

| 字段/动作 | 约定 |
| --- | --- |
| 账号 | 文本框、必填、允许粘贴，提交前只去除首尾空白；不擅自猜测邮箱或手机号格式。 |
| 密码 | 密码框、必填、允许粘贴与密码管理器；不 trim、不放入 store/日志/本地存储；关闭表单清除。 |
| 登录 | 非空后可提交，提交中阻止重复动作；错误就近显示“账号或密码错误”或归一化网络错误。 |
| 关闭 | 返回原面板、保留行程和非敏感输入，焦点回到触发入口；取消后不执行原待办动作。 |
| 退出登录 | 从账号菜单进入；有未保存修改时先选择保存或放弃/返回编辑；成功后清除用户列表、记录及对话缓存。 |

保存、打开“我的行程”或生成模拟记录需要身份时直接打开登录框。表单主动作按上下文为“登录并保存 / 登录并查看 / 登录并记录”，成功后核对属主和待办快照再继续原动作，不让用户重新填写行程。明确 401 才进入恢复身份流程；超时结果未知的写操作按交接约定核对结果，不能盲目重发。

Session 失效时保留当前内存草稿并暂停持久化，入口可重新登录；恢复为同一账号可继续。切换成其他账号时不得把原账号的行程、消息或记录自动写入新账号，先处理草稿并清除旧身份缓存。403/404 不按登录成功后自动重试处理。这里定义登录/退出闭环，账户创建方式由任务 23 的契约确定，不增加注册或找回密码流程。

### 4.4 我的行程

顶栏“我的行程”打开现有左侧工作面板，移动端打开同一底部抽屉；头部只保留标题、返回和“新建行程”。登录态、加载态、空态、失败态分别明确；空态仅“暂无行程”与新建动作，失败提供“重试”。

- 列表项：行程名、起终城市摘要、出发日期、最近保存/修改时间；城市数、完整城市链、历史版本在详情中查看。首次默认名为“起点 → 终点”，不具备起终点时用“未命名行程”。
- 按服务端 `updatedAt` 倒序，同时间按不透明 ID 稳定排序；每批 20 条，“加载更多”仅在有下一批时出现，不构成总数上限。
- 点击列表项恢复为当前行程并回到路线页签；已有未保存修改时执行 §4.2 的保存/放弃/继续编辑选择。恢复后核对历史版本，旧候选不能冒充已重算结果。
- “更多”菜单提供重命名、删除。重命名在该列表项内编辑，必填，限制 1–40 个 Unicode 码点；服务端重复校验。超长默认名按显示规则截断，编辑时仍能查看完整原名。
- 删除前用行程名确认，删除中禁用重复操作；成功才移除列表项，失败保留。删除正在打开的已保存行程时，转为未保存草稿并清空持久化 ID；已有模拟记录保持独立，不级联删除或改写。

### 4.5 模拟记录的入口、列表与详情

账号菜单提供唯一的“模拟记录”入口，复用工作面板/移动抽屉。模拟确认成功后提供“查看记录”，直接进入同一详情；返回可回到列表或原路线，不丢失当前草稿。

列表按创建时间倒序，每批 20 条：记录编号、起终站摘要、计划出发日期、历史金额或“金额未知”，列表头统一标“模拟”。空态为“暂无模拟记录”，加载/失败可重试；不添加支付、出票、退票或取消状态。

详情显示：记录编号和生成时间、城市及分段发到站、车次、完整日期时刻、席别（有数据才显示）、历史区间价格/缺失项、数据版本与来源。详情头保留“模拟”短标记；创建确认时显示一次“不会扣款或生成真实车票”。记录使用创建时的方案快照，之后改线、改名、删行程不改写快照。

生成前必须有已选且在当前条件下完成历史车次/时刻匹配的方案；余票不是前置条件。历史价格缺失允许记录“金额未知”，不伪造金额。生成期间禁止重复确认；超时后的结果核对与重复请求去重见交接约定。列表/详情均须服务端校验属主。

### 4.6 日期与条件控件壳

| 字段 | 控件与初始值 | 校验和短文案 |
| --- | --- | --- |
| 城市顺序/车站 | 引用当前节点列表，站名可编辑 | 至少两个有效城市节点；缺项定位到节点，“请补充起终城市 / 请选择车站”。 |

### 5.2 字体与排版

- 中文默认采用系统字体栈：`"PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", system-ui, sans-serif`；确有辨识与阅读收益时可使用外部字体，保留系统回退。
- 产品名称和站名通过字重与位置建立层级，不使用大幅英文标语、全大写标签或无关装饰字体。
- 面板标题 20/28、字重 600；分组标题 16/24、600；正文与输入 14–16/22–24、400；辅助文字 12/18。站名、时刻、错误提示不能使用低于 14 的主字号。
- 出发/到达时刻使用 24/28、600，车次 16/24、600，价格 18/24、600。数字采用等宽数字特性，历史金额按币种显示两位小数，并注明数据年份/版本。
- 段落与说明左对齐。长站名可换行，不能只靠截断后的相同前缀让用户猜测；完整名称应可直接获得。

### 5.3 间距、形状与图标

- 使用 4、8、12、16、24、32 的间距尺度；面板内边距 16，分组间距 24，同组行间距 12。
- 搜索栏/主要面板圆角 16；菜单与提示浮层 12；按钮与输入框 8；小状态标签 4。头像可为圆形，其余控件不统一胶囊化。
- 主要悬浮容器阴影为 `0 6px 24px rgba(23, 33, 43, 0.14)`；小菜单用 `0 2px 8px rgba(23, 33, 43, 0.10)`。普通列表行通过间距和细线分隔，不逐行叠阴影。
- 浮层默认不透明白底；不以毛玻璃承载正文，也不依赖背景模糊维持层级。
- 图标采用一套线性样式，视觉尺寸 20–24，描边约 2；可使用已有资源、原生 SVG 或有授权的外部图标素材。功能按钮不用 emoji 代替图标。

### 5.4 基础组件状态

| 组件 | 设计规则 |
| --- | --- |
| 主按钮 | 高 44，主蓝底白字；同一区域只突出一个当前主要动作。悬停加深，焦点有轮廓；处理中显示动作文字与指示，例如“正在查询”，并阻止重复触发。 |

### 5.5 外部资源

## 6. 地图、城市与铁路线路

### 6.1 图层和标记

图层从下到上为：真实底图 → 已取得几何的备选方案 → 当前方案白色外衬/深绿描边/亮绿内芯 → 方向箭头 → 城市/车站及起终标记 → 选中节点信息浮层。普通铁路背景与当前方案必须能区分；实际宽度和状态见 §6.3。

| 对象 | 表现规则 |
| --- | --- |
| 用户有序城市节点 | 中间节点使用约 28–32 的编号标记，旁列城市名；序号只表达用户行程顺序。起点/终点使用 §6.3 的“起 / 终”水滴标记。 |
| AI 建议但未确认城市 | 节点旁明确写“建议”，详情有“采用城市 / 更换城市”；不能显示为用户已指定。 |
| 实际发到车站 | 约 10–12 的圆点配站名；详情显示所属城市及发/到属性，不和城市序号混用。 |
| 当前选中铁路区间 | 亮绿内芯、深绿描边与白色外衬，选中段适度加粗；方向沿实际有序铁路几何，参数见 §6.3。 |
| 其他候选方案 | 浅绿低强调线并标识“备选”；只有已取得实际几何时才绘制，选择后提升层级，不自动确认车票。 |
| 有几何但尚待历史时刻匹配的预览 | 沿取得的铁路几何用绿色虚线，并标注“路线预览 · 历史时刻待匹配”；内芯与描边的断点对齐，虚线仅表示状态，不能代替几何来源。 |
| 几何缺失或与车次对应关系未知 | 标注已知节点，缺失区间不连线，列表说明“铁路轨迹暂不可用 / 车次与轨迹待匹配”。 |

不能用城市直线、起终站连线、若干站点的折线或道路算路代替实际铁路。通用铁路网络图层可作为背景，但不能仅凭其存在就宣称当前车次路线已验证。几何与车次匹配、来源、获取时间在区间详情可查。

### 6.2 视野与联动

- 首次进入展示中国范围的浅色地图；视野不表示已接入全部城市数据。已有当前行程时适配该行程，而非每次回到全国。
- 点击地图上的可选城市或铁路站标记即按顺序加入同一行程。点城市由系统匹配车站，点铁路站保留所选站码作为用户指定站，搜索结果也加入同一行程。从第二个节点起自动重算。拖动、缩放和点击空白地图不追加节点。
- 高德视图复用底图原有的城市、铁路站标注与点击热点。城市按名称唯一匹配本地目录，比较时允许省略市级后缀。铁路站按站名和坐标核对固定 GTFS 目录，多个匹配站码交用户选择。未展示或无法匹配的城市、铁路站可通过本地搜索加入行程。
- 等距投影使用本地城市标记，放大至局部视野显示目录铁路站。站点命中区域重叠时，打开站点选择列表，按站名、站码和所属城市区分。行程已有的站点标记打开对应节点或车次详情。
- 点击已选节点打开该节点详情，不因重复点按自动增加相同条目；这条反馈规则不裁决返程/重复到访的业务支持范围。
- 选择城市行定位城市，选择发/到站定位车站，选择车次区间高亮对应实际轨迹；地图选中也同步列表，可见焦点不被内部滚动区遮挡。
- “查看全程”适配全部当前节点和已取得的铁路轨迹，并为缺失区间显示状态。仅悬停不反复自动缩放。
- 不自动索取定位权限；未确认使用当前位置的需求前，不放置会暗中定位的按钮。

等距投影的全国视野默认最多显示 24 个普通城市标签；这是标注密度限制，不限制可搜索/可选城市。普通标签先按本地 `labelPriority`、再按稳定城市 ID 排序，投影到屏幕后在 96 × 48 的网格中每格最多保留一个，并做文字包围盒碰撞检查；缩放进入局部后按可用网格逐步增加。

用户节点、当前起终点、选中区间站点优先显示，用户节点重叠按 §6.3.3 展开列表。高德视图的普通城市和铁路站标注统一由高德绘制，RailFlow 覆盖物仅用于当前行程的标记、轨迹和相应标签。

### 6.3 路线组件（第二张参考图）

#### 6.3.1 组件组成与主线

路线组件由实际铁路轨迹、可用的备选轨迹、静态方向箭头、起终标记、途经/站点标记，以及节点详情和状态图例组成。它覆盖在真实底图上，复用主页已有面板；不另建路线大屏或复制截图中的右上工具栏。箭头与节点沿数据所指向的铁路走向放置，不临摹截图中可能属于其他交通方式的曲线。

在桌面标准缩放下采用以下屏幕尺寸，单位为 CSS px：

| 部分 | 视觉参数 | 规则 |
| --- | --- | --- |
| 当前路线 | 白色外衬总宽 16 → 深绿描边总宽 12 → 亮绿内芯总宽 8 | 三层使用同一条几何；线帽和连接为圆角，不通过平滑曲线切离真实轨道。 |
| 当前选中区间 | 外衬/描边/内芯总宽 18/14/10 | 仅比其余当前路线适度加粗，端点与面板选中同步；焦点不靠颜色单独表达。 |
| 备选路线 | 白色外衬总宽 12 → 备选深绿边缘总宽 8 → 浅绿内芯总宽 5 | 用浅色实体填充降低强调，不对整个可点击组件统一降低透明度；标注“备选”。 |
| 待核验预览 | 沿有来源的轨迹使用约 12 实 / 8 空的绿色虚线 | 各层断点对齐；不留下连续实心描边，避免预览看起来已核验。白色外衬仅承担与底图的分隔。 |
| 方向箭头 | 白色箭头约 6–8，使用独立的 `--color-route-arrow-outline` 深色细衬边约 1 | 放在当前路线内，不承担按钮功能；浅色主线不能直接使用无衬边白箭头。 |

普通当前路线保持连续的绿色视觉。某段缺失、不连续或未能匹配目标区间时，该段留空并显示缺失说明；不能为了主线完整，把两端用直线、道路或跨越缺口的箭头接起来。

#### 6.3.2 起点、终点与途经节点

| 标记 | 视觉与尺寸 | 语义 |
| --- | --- | --- |
| 起点 | 约 36–40 宽、44 高的水滴标记，深绿填充、白色“起”、白色外缘约 3；尖端锚定坐标 | 当前行程首次出发位置。 |
| 终点 | 与起点同形同尺寸，红色填充、白色“终” | 当前行程最终到达位置；不是错误或无票。 |
| 用户途经/停留节点 | 约 28–32 的黄色圆形编号标记，数字和边缘使用深色，外加白色分隔边 | 只表示用户城市顺序；“仅途经 / 停留 N 天”另用文字说明。 |
| 实际铁路车站 | 约 10–12 的白底深色小圆点，选中时显示完整站名 | 用于具体上下车站，不自动成为用户停留节点。 |

“起 / 终”字与节点编号至少 14、字重 600；可点区域至少 44 × 44，小标记可扩展透明命中区域。城市名与站名放在带白色衬底的短标签中，不能把一串长站名塞入水滴标记。

已匹配具体车站时，路线的起终标记锚定首段实际上车站和末段实际下车站；行程摘要仍显示所属城市。未匹配车站时可标出城市层面的起终预览，但需写“待匹配车站”，不能用城市中心点冒充站点。中间停留节点的到站/发站不同，分别标注两个站，不把二者合成一个坐标或补画未经核实的接驳。

标记位置服从坐标，只移动标签避让并在必要时加引线；不为避开遮挡而把轨迹或站点搬到错误地理位置。不复制图中的蓝色定位光圈，也不制造实时车辆/用户位置效果。

#### 6.3.3 方向、重叠与缩放

- 箭头按各乘坐区间从出发站到到达站的顺序，沿有序轨迹局部切线定向；不能用屏幕上下、经纬度大小或多边形绘制方向猜测行进方向。
- 箭头以约 80–120 的屏幕间距分布，避开起终标记、途经点、站名和急弯。很短的区间可不放箭头，改由起终标签与文本顺序表达方向；不为凑箭头延长或改造铁路几何。
- 默认静态箭头，不使用流动粒子、循环移动箭头或模拟列车动画。待核验的虚线预览不放容易造成“正在运行”误解的动画。
- 主线与备选共用的路段，当前路线绘制在上层；在真实分叉处体现差异。不能将重合轨迹人为横移成两条并行铁路；重合区间通过可选方案列表或浮层区分。
- 缩放只调整屏幕线宽、箭头密度与标签数量，不改变节点顺序、坐标或真实走向。概览时可隐藏普通经停站标签，保留用户城市节点和起终点；查看局部时再展开对应站名。
- 起终点或多个节点重叠时，显示可展开的节点列表和“起 / 终 / 途经”角色；可通过查看局部或面板选择定位，不吞掉其中一个节点。

#### 6.3.4 选择、状态和联动

- 鼠标悬停/键盘聚焦区间时适度加粗或显示边缘反馈，并给出对应城市/车站和区间名称；不自动改变方案或频繁缩放。
- 点击当前轨迹时选择对应区间并打开面板内详情，列表、站名和高亮同步；此操作不能落入底图的“添加城市”事件。透明线条命中宽度桌面可取约 24，触屏至少 44；重叠命中时提供区间/方案选择，不能永远选中最上层的一条。
- 点击备选只切换查看/选择的候选方案，主线、箭头和对应车次结果一起切换；不改变用户已确认条件，不自动保存或模拟预订。备选的几何或历史数据不足时，明确显示缺失状态。
- 图例和详情区分别表达“当前路线 / 备选路线 / 路线预览”、历史时刻衔接及票价完整性。价格缺失不把整条路线变红，几何存在也不能直接显示为全程可衔接；说明“历史数据参考，未核验当前余票”，不提供余票状态图例。
- AI 多轮改线、手动排序或恢复行程后，轨迹、箭头、起终角色与节点编号均取自同一当前行程；旧响应不能拼入新路线，删除的节点不能留下标记。
- 后续实现须能将轨迹、标记和命中对象关联到同一方案/区间/节点，并取得有序几何、坐标体系、节点角色、来源和当前核验状态；这是渲染所需的信息边界，不在本规范中新增接口或固定数据结构。

### 6.4 本地与高德地点查询

- 本地城市及铁路客运站由项目后端提供；车站可包含普速、高铁服务，同一站不因类型重复展示。城市归属、站名/别名与铁路标识以本地基础数据为准。
- 输入时匹配本地城市和车站。「搜索高德地点」按钮使用当前关键词向项目后端发起查询。同词重查时旧高德结果可查看，暂时停用选择和关联确认；失败后恢复原有效结果。换词后清除旧地点结果，本地搜索独立可用。接口与错误状态见[地点查询 §8.1](design-spec.md#81-本地点位与高德地点查询)。
- 结果分为「城市」「铁路站」「高德地点」。高德结果显示名称、城市、区县和地址。可见信息相同时附上高德地点 ID，详情始终显示来源与 ID。
- 选择高德结果后，地图用独立的地点图钉定位，搜索区展开地点详情。详情用地点所属城市预填本地查询，用户可改查城市、站名或站码。选中本地结果后显示待确认的城市或站码，点击「确认并加入行程」才追加节点。城市由规划选站，铁路站保留所选站码。
- 本地关联无结果或查询失败时保留地点详情和已有行程，支持换词或重试。关闭详情或更改主搜索词会清除地点预览与待确认关联。地点预览与全程视野分别计算。
- 高德失败、无结果或配额/权限不足就近给短提示；本地查询和已有行程继续可用。底图加载失败另行表达，不能因为本地有点位就宣称整张地图离线可用。
- 地点、车站与铁路轨迹按来源坐标系统一后绘制，避免重复转换；高德地点结果不代替实际铁路几何。界面只显示必要结果和状态，完整来源放详情，不另加常驻解释卡。

### 6.5 GTFS 初测与回放显示

- 只接收当前固定版本、方案与乘坐区间对应的已排序/裁剪几何；关联、服务日校验和坐标转换由后端/地图适配能力按需求 §8.2 提供，前端不直接加载全国 shapes，不按车次名猜轨迹或把站序当轨迹下标。
- 主日期显示行程日期，“今天”仍为实际北京时间；列表头统一短标“历史回放 · 参考日期/版本”，详情展示参考服务日及原始发到时间。D0/R0 与统一日偏移由服务端提供并随行程保存，恢复时不按今天重建；不强制去年同月同日。
- GTFS `26:06:00` 等累计时刻经服务端按固定北京时间 `UTC+08:00` 换算后，以完整行程日期、24 小时制钟点和 `+N 天` 显示。参考服务日可早于途中上车日。日期越界、无开行记录和缺 shape 分别表达，已有输入与有效段保留。
- 初测依次覆盖南京南→上海虹桥直达、北京南→南京南区间裁剪、北京→南京→上海自然日停留，再追加北京→哈尔滨跨日。实际车次/日期由固定包核验，不把候选样例或合成夹具标为真实运行通过。

## 7. 城市路线编辑与车次结果

### 7.1 搜索和组线

搜索结果明确区分“城市 / 车站”，显示省份、所属城市与完整名称；同名结果必须让用户选择，不能任取第一个。选车站时同时展示其所属城市以及将影响哪个路线节点；不静默把城市路线替换成孤立车站路线。

路线节点按用户顺序竖排，默认显示城市、到/发车站和停留值；修改、移动和移除在选中节点或更多菜单中提供，不逐行铺开所有按钮。拖拽只作增强，排序操作也须可通过点按和键盘完成。长路线在面板内滚动，不设固定节点数来迁就布局。

点选多站城市且用户尚未指定车站时，展示服务端按 `stop_id` 字典序匹配的首个可行站。候选站全部无可行路线时，保留城市节点，隐藏对应的路线结果和地图轨迹。车站通常只显示站名，尚未匹配时显示“待匹配”。站点编辑详情注明实际匹配站及其来源，用户可改站并以指定站重算。同城跨站衔接未核实时不显示“换乘可行”。

主页使用同一份有序行程，移除独立“两站直达”入口和手动匹配按钮。新增或编辑城市、到发站后自动重算，加载时标明受影响的区间，旧响应不能覆盖修改后的结果。点选的停留城市与系统安排的换乘点分别展示，跨站显示实际到站和下一程离站。列表和地图同步显示所选车次区间；找不到可行路线时保留用户选择并标记对应区间。详见 [城市行程历史回放](city-replay.md)。

停留节点默认只显示“停留 1 天”，自然日口径放入停留设置的按需提示。例如 11 月 16 日 20:00 到达，默认可于 11 月 17 日出发；日期与车次按当前数据规则校验。起点出发日期与终点到达信息分别呈现，不额外强加停留。零天停留的含义及校验规则待业务确认，前端不另定计算公式。

修改城市顺序、站点、停留或出发日期后，立即标明受影响及后续日期依赖区间“待重新计算”。旧方案若保留供对照，必须去除“当前有效”状态并禁用基于旧结果的确认动作；不能让新路线沿用旧历史票价匹配或旧衔接结论。

### 7.2 车次方案展示

方案摘要突出城市顺序、列车换乘次数、发到日期/时刻、总耗时和历史费用性质；默认说明“优先换乘最少”。服务端按所选历史版本完成校验后，才标注该版本内直达、可衔接或满足停留条件，不承诺当前开行或可售。

单个区间至少展示：车次 → 发站/到站 → 完整日期与时刻 → 席别和历史票价/未知 → 数据版本与时间/来源。跨日同时显示完整日期和“次日 / +N 天”，只写时分不足以表达衔接。日期与相对日期按服务端北京时间口径显示；若使用历史回放业务日期须显式标明，不暗改“今天”。总耗时包含途中等待和用户安排的停留，必要时展开乘车/等待/停留明细。

- 换乘次数使用服务端结果；不能按前端卡片数减一计算。同一列车运行实例的途经/分段展示不额外计次。
- 同站换车也计一次；跨站衔接需显式显示到站与下段出发站，不能以同城名称掩盖站点不同。
- 同换乘次数的次级排序尚未定稿，界面不承诺“最快 / 最便宜”已生效，也不自行改变服务端排序。
- 发到站必须是本段实际乘坐区间，不能用整趟列车始发/终到站替换；历史票价对应可核对的数据版本、乘坐区间和席别，列车身份须区分适用日期，不能仅靠同名车次拼接不同年份数据。
- 费用统一表达为“历史票价 ¥123.00（数据年份/版本）”等金额及其性质，不承诺当前售价。若部分价格缺失，显示“已知历史票价合计 ¥…，另有 N 段价格未知”；缺失不计为零，不把已知合计称为完整总价，也不自动补模拟价格。
- 区分历史时刻未匹配、不可衔接、日期不覆盖、载入失败和历史票价未知；缺少票价不自动删除可衔接路线，也不能据不完整金额承诺满足预算。
- 保留历史来源、快照/适用版本和导入时间；本地读取时间不能冒充历史价格采集时间。当前不展示“有票 / 无票 / 未开售 / 候补 / 可售”等余票状态，不假定全部有票。

### 7.3 最简模拟预订

仅在已选择符合已定历史数据校验条件的交通方案后提供“模拟预订”，打开紧凑确认层，列出所选区间、席别、历史费用/价格未知和“不会扣款或生成真实车票”。确认按钮为“确认模拟预订”，结果为“模拟预订记录”；不以实时余票核验作为前置条件。不恢复锁座倒计时、模拟支付、退款或票务管理模块；保存行程不自动触发预订。

### 7.4 多方案列表与比较

查询结果以同一面板中的纵向方案列表呈现，不额外堆一个常驻比较面板。桌面和移动端默认显示前三项，超过时“更多方案”展开其余服务端结果；三项是折叠数，不是搜索/换乘次数限制。

每张摘要卡使用同一字段顺序：方案序号/选中态 → 换乘次数 → 首次出发及最终到达时间（跨日有 `+N 天`）→ 含等待/停留的总耗时 → 历史总价或“已知 ¥… · N 段未知”。数据版本统一放列表头，不逐卡重复；版本不同时在该卡短标。缺价格的方案仍可选择，不声称满足预算。

服务端已按换乘最少给出顺序，前端保持原序；同次数不额外按耗时或价格排序。选择卡片或地图备选线会同步同一 `selectedCandidateId`、实际几何、方向/节点、分段车次与摘要。选中卡展开区间，其余保持摘要；点击详情中的返回保留选中项和列表位置，不重新查询。

用户可勾选 2–3 个方案后点“比较”，在面板内临时显示以方案为列、换乘/发到时间/总耗时/历史费用/缺失项为行的比较表；移动端按指标分组纵向排列，避免横向挤压。退出回原列表，不改用户条件。选中/勾选是两种状态，比较本身不保存或模拟预订。无结果、部分成功和条件变更后的状态见 §9.1。

## 8. AI 助手与保存行程

### 8.1 对话与规划结果

- 入口使用“AI 助手”，输入框占位语为“想去哪里？”。空会话不放介绍气泡、能力清单或多段操作指引，不伪造已经生成的聊天历史。
- 当前出发地、目的城市、途经顺序、日期、停留和其他已表达条件以可展开摘要呈现。AI 的解释不替代可编辑路线。
- 缺必要信息时明确指出缺什么，例如“从哪个城市出发？”；可先展示有依据的候选城市或地图节点，历史价格按明确版本展示，不说成当前售票报价。
- 对“想去新疆”，可显示“建议以乌鲁木齐为目的城市，可更换”，并给可修改预览；不得在用户消息中伪造其已经选择乌鲁木齐。
- 追加“途经郑州”后保留已有条件，更新同一行程和地图；可短答“已加入郑州”，不重复整份行程。冲突时只指出需要处理的具体条件。
- “途经”需区分仅经过、换车与下车停留；含义不明确时补问。默认一天只用于用户选择的停留节点，不扩展到列车全部经停站或 AI 补齐的网络节点。
- 结构化规划结果在聊天中提供“查看路线”，跳转到同一工作面板的路线页签；不为每条消息创建一张与当前地图脱节的静态行程。
- 消息生成中允许看到处理状态；未完成的文本不作为已核验结果。请求失败保留原输入和已有行程，提供重试与手动选点入口。

### 8.2 保存与恢复

当前视图只保留顶部“保存行程”入口；无可保存内容时禁用，必要原因按需查看。保存中、已保存或失败直接在该入口呈现，未保存修改用简短状态表达，不再叠加同义提示段落。

保存对象应能恢复意图与偏好、有序城市、起终目标/建议目的城市、车站选择、停留、生成方案与解释、线路来源、历史时刻/票价版本及来源时间，以及 AI 个性化输出与地图的关联；用户明确条件、AI 建议和工具事实分别表达。最小服务字段和覆盖/另存/版本冲突按交接约定实现，具体 HTTP 契约交任务 23；长期偏好仍待需求确认，不自动保存或跨方案沿用记忆。

恢复后显示保存时间与统一历史版本短标，完整来源按需查看；保存不表示当前真实开行或可售。条件或版本改变时显示“需重新计算”，不依赖实时票务刷新。登录与身份恢复按 §4.3，行程入口按 §4.4；并发保存按 [交接约定](../../handoff/20261116-22-frontend.md#store-contract) 执行。

## 9. 状态、反馈与异常

线路几何、历史时刻衔接和历史票价完整性分别表达，允许出现“几何已取得、历史车次待匹配”“历史车次已匹配、轨迹缺失”或“可衔接、历史票价未知”。缺失的能力必须如实显示，不能把整张方案一律标成成功或失败；本轮不处理余票状态。

| 情况 | 用户可见反馈 | 可继续的动作 |
| --- | --- | --- |
| 空行程 | 保留搜索、选点和 AI 输入入口，不另加说明卡 | 地图选点、城市/车站搜索、AI 输入。 |
| 条件不完整 | 在对应字段或节点旁说明缺项 | 补充条件；保留已有节点和输入。 |
| 查询中 | 对受影响区间展示轻量骨架和“正在查询车次” | 浏览地图和已有信息；重复查询按钮暂不可重复触发。 |
| AI 正在处理 | 明确生成状态，不显示编造的进度百分比 | 继续查看当前行程；保留输入。 |
| 没有可行车次 | 指出具体区间、日期和已知原因 | 修改日期、车站或路线，重新查询；不自动放宽约束。 |
| 几何缺失 | 地图保留节点，区间显示“铁路轨迹暂不可用” | 查看已知车次或重试；不填上假线。 |
| 局部查询失败 | 保留其他段，失败段显示原因与数据时间 | 只重试受影响部分；后续依赖结果保持待核验。 |
| 历史版本或条件改变 | “需重新计算”，取消旧匹配/衔接结论 | 重算受影响段，不沿用旧结果继续确认。 |
| 地图服务不可用 | 地图区域说明失败；已取得的文本路线仍可查看 | 重试地图、搜索或编辑现有路线；不放示意轨迹冒充实际铁路。 |
| 保存失败/登录状态失效 | 保留本次编辑，说明保存未成功 | 重试或按既定账号流程恢复身份。 |

错误信息就近放置，包含对象、原因和下一步；完整错误体不直接暴露给用户。toast 只用于非关键确认，可关闭，不能作为唯一的错误或保存状态载体。

连续修改触发并发请求时，迟到响应不得覆盖更新的城市顺序、AI 条件或当前地图；必须以当前有效查询条件为准同步列表、几何、价格与状态。此处规定可见行为，不预设接口版本号或请求协议。

### 9.1 组件级状态矩阵

`state` 为前端归一化状态名；本表决定控件行为，§9 的场景表决定信息放在哪里。未满足本轮范围的业务状态不补成成功；错误正文使用交接文案表。

| 组件 | state / 进入条件 | 呈现与可用动作 | 退出/恢复 |
| --- | --- | --- | --- |
| 搜索 | `idle`：空串或清除 | 无结果面板，输入可用 | 输入进入 typing；清除使旧请求失效。 |
| 搜索 | `typing`：文本已变且不在组合期 | 保留输入，旧结果不可选；250ms 防抖 | 归一化查询键相同不重复发起。 |
| 搜索 | `composing`：输入法组合期 | 只更新输入，不请求、不选结果；Enter/Escape 交输入法 | 见 §11.1；组合结束后查询最终文本。 |
| 搜索 | `loading`：本地/高德请求待返回 | 一个就近加载指示；可继续输入/取消，旧选项不可选 | 当前请求返回 ready/empty/error。 |
| 搜索 | `ready`：有匹配项 | 分组结果、方向键/点按选择；每项保留类型、所属城市 | 选择关闭列表，编辑文本重新 typing。 |
| 搜索 | `empty`：当前查询无结果 | 单行“未找到地点”；不能用 Enter 添加不存在实体 | 修改查询或清除。 |
| 搜索 | `error`：部分或全部查询失败 | 保留输入；高德失败仍保留有效本地组，只给失败组“重试” | 重试当前键，不重置路线。 |
| 搜索 | `offline`：无法发出请求 | “离线”；仅已载入内存的本地候选可选，未载入不冒充可查 | 连通后用户重试，不自动加入节点。 |
| 日期/条件 | `loading`：能力配置未返回 | 路线可编辑；条件区轻量加载，查询暂不可用 | 配置 ready 后按字段定义渲染，失败可重试。 |
| 日期 | `valid`：合法且在已知范围 | 正常回显，满足其余必填项即可查询 | 编辑触发校验并使旧结果待重算。 |
| 日期 | `invalid`：空值提交、非法日期或越界 | 字段错误短文案，查询不可用；不自动替换为今天 | 修正后移除错误，不丢其他输入。 |
| 停留 | `valid / invalid`：正整数 / 空、负、0、小数等 | 合法回显；非法标“停留天数需为正整数”，不重算新结果 | 修正后再计算，不自动 clamp 为 1。 |
| 日期/区间 | `crossDay`：到达跨自然日 | 不属于错误；摘要时刻显示 `+N 天`，详情有完整日期 | 下段日期由服务端重新计算。 |
| 方案卡 | `loading`：当前 revision 查询中 | 三张摘要骨架或已有结果加“待计算”；禁止确认旧方案 | 当前结果返回后替换，保持用户滚动位置。 |
| 方案卡 | `ready`：当前条件与版本已匹配 | 可选择、比较、查看区间；模拟动作按 §4.5 条件 | 用户改条件进入 stale。 |
| 方案卡 | `partial`：几何、时刻或价格部分缺失 | 分别短标；价格未知仍可看/选，历史时刻未匹配不可生成记录 | 重试失败能力，保留其余结果。 |
| 方案卡 | `stale`：条件/版本变化 | “待计算”，禁用基于旧快照的模拟确认；不清空城市输入 | 当前 revision 重算后才恢复 ready/partial。 |
| 方案卡 | `empty / error`：无匹配 / 载入失败 | 分别“无匹配方案”或错误+重试，不能混为无票 | 改条件或重试。 |
| AI 消息 | `pending`：已提交但尚无文本 | 单个生成指示，保留用户消息；同轮不重复发送 | 首段文本到达进入 streaming。 |
| AI 消息 | `streaming`：正文增量到达 | 更新当前气泡；用户已向上滚动时不强制吸到底部 | 完成后一次性校验并提交结构化改线。 |
| AI 消息 | `complete`：正文与结构化结果完成 | 可查看路线；每个结果补丁只应用一次 | 新输入开启新请求。 |
| AI 消息 | `failed / interrupted`：失败或停止 | 保留已有文本但标未完成，提供“重试”，不应用半成品路线 | 同一用户消息开新 requestId，替换失败回答，不复制用户消息。 |
| 地图 | `loading`：底图初始化 | 地图区加载，搜索与文本行程可用；地图命中暂不可用 | ready 后挂载当前 revision 的覆盖物。 |
| 地图 | `ready`：底图与所需覆盖物可用 | 地图正常操作；各区间缺失仍单独表达 | 数据改动只更新受影响覆盖物。 |
| 地图 | `degraded`：底图不可用/SDK 失败 | 错误+重试，保留文本方案和当前输入；不贴静态图假装加载成功 | 重试后沿当前选择恢复，不重置方案。 |
| 登录 | `submitting / failed / expired` | 阻止重复提交；失败就近提示；失效保留草稿并要求重新登录 | 按 §4.3 校验身份后继续。 |
| 保存 | `saving`：已发出快照 | 禁止第二个保存请求，但允许继续编辑 | 只把提交的 revision 记为已保存。 |
| 保存 | `dirty / saved / conflict / unknown` | 分别为未保存、已保存、版本冲突、结果待核对 | 冲突不静默覆盖；结果未知先按请求 ID 核对，见交接约定。 |

### 10.1 移动端操作细节

- 折叠态仅显示 56–72 高的摘要与 44 高的展开命中区；半屏态为可视区域约 50%；展开态顶部停在搜索栏下方，底部避开安全区与地图署名，三档均有按钮操作。
- 顶部固定搜索（56 高、外边距 12）及一个“更多”入口；保存、我的行程、模拟记录和账号收进该菜单，当前视图仍只有一个保存入口。打开 AI/路线复用抽屉，不叠两个面板。
- 抽屉只有头部手柄响应拖拽，内容区负责滚动，文本选择和输入不触发拖动；拖到边界不把手势透传为误加城市。地图在抽屉之外仍可操作。
- 搜索获得焦点时展开结果区；选中后回到先前抽屉档位并定位对象。打开节点编辑/方案详情/行程/模拟记录，用抽屉内层级和一个返回按钮；返回保留上层滚动与选中状态。
- 登录使用模态表单，内容超高时内部滚动；比较在抽屉内按指标纵向排列，主动作留在底部可见区，不靠横向滚动才能找到。
- 软键盘弹出时依据实际可视视口重新计算输入区位置，不能仅假定 `100dvh` 会处理全部键盘行为；发送、错误提示和登录按钮都须实机核对。地图署名按供应商要求持续可见，必要时减小抽屉占高。
- 200% 缩放或可用宽度 320 时降为单列可滚动详情，保留关闭/返回，站名换行、图标命中区不缩小；无全局横向滚动。

## 11. 可访问性与动效

- 正文和辅助字的文字/背景对比度目标至少 4.5:1；大字号文字、关键图形、控件边界和焦点识别目标至少 3:1。装饰性分隔线不承担唯一识别责任。
- 常用点击目标至少 44 × 44；小图标保留足够内边距。图标按钮有可读名称，hover 提示不能成为唯一说明。
- 颜色以外同时使用文字、起终标签、节点编号、实虚线和状态图标表达含义；不能只用红绿区分可衔接与不可衔接。
- 搜索结果支持方向键、Enter 和 Escape；表单有持久标签。Tab 按可见逻辑进入搜索、主动作、面板及地图工具，焦点用约 2px 主蓝轮廓并保留间隔。
- 面板关闭后焦点回到入口；模态框约束焦点并允许合适的关闭路径。地图不能造成键盘焦点陷阱；城市搜索、排序和文本区间列表可完成选点/改线的等价操作。
- 重要状态变化提供可被辅助技术读取的提示，避免逐字播报 AI 流式文本或频繁地图移动。路线/车次信息有文本等价内容。
- 状态切换约 120–180ms，面板展开约 180–240ms；地图仅在明确定位/查看全程时平移缩放。尊重减少动态效果偏好，无自动巡游、持续流光轨迹和循环呼吸标记。

### 11.1 中文输入、日期与长文本

搜索记录 `compositionstart/end` 的组合状态，并以事件 `isComposing` 作补充判断；组合期间只更新文字，取消待发防抖，不发请求。用于确定中文候选的 Enter 不提交搜索/添加节点，Escape 不清空输入或关闭应用面板。组合完成或取消后读取输入框最终值，按 250ms 防抖与查询键去重处理；同次组合后的 `input` 不重复请求。普通状态下 Enter 只选择当前有效候选，Escape 关闭结果而不清空已提交城市。组合事件含义见 [MDN compositionend](https://developer.mozilla.org/en-US/docs/Web/API/Element/compositionend_event)，判断范围见 [isComposing](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/isComposing)；不能只依赖后者，应在设备矩阵中实测事件顺序。

| 内容 | 产品文本格式 | 数据约定 |
| --- | --- | --- |
| 日期字段/方案头 | `2026-11-16` | 值为日期字符串 `YYYY-MM-DD`，不以 UTC 午夜转换；原生日期控件外观可随浏览器本地化，但取值一致。 |
| 折叠方案时刻 | `23:40 → 01:10 +1 天`，头部有出发日期 | `+N` 为服务端业务自然日差；跨年也适用。 |
| 区间详情 | `2026-11-16 23:40 → 2026-11-17 01:10` | 运行日期/时刻与历史适用版本都保留。 |
| 保存/模拟记录时间 | `2026-11-16 08:00` | 服务端带偏移的 ISO 时间戳；客户端显式以 `Asia/Shanghai` 和 24 小时制格式化。 |
| 历史价格版本 | `历史票价 · 2025 版` 或真实版本名 | 年份不是行程日期；模拟/历史参考各只在必要位置标一次。 |

时间格式采用 [Intl.DateTimeFormat](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat) 的时区选项或等价的统一格式函数；不得受浏览器所在时区改变。空值显示“未知”而非 `Invalid Date`。日期回放按需求 §6.2 的固定锚点与日偏移由服务端提供，能力配置未就绪时允许编辑但暂不查询，不宣称今天真实开行。

中文说明段落以约 35–40 汉字为最大舒适行宽，可用 `max-inline-size: 40em`；窄面板自然更短，不为凑字数放宽面板。站名和关键字段允许换行，连续英文/ID 使用 `overflow-wrap: anywhere`；卡片标题可截为两行，但完整名称可点按/键盘查看。搜索消歧和区间发到站不靠只有相同前缀的省略文本辨认。

## 12. 实现交接约束

- 前端保持 `src/frontend/` 原生 HTML、CSS、ES Modules，不引入 React、Vue、Node.js、npm 或打包器；外部视觉资源按 §5.5 使用。
- 尺寸、颜色、间距和层级通过 CSS 自定义属性集中管理；图标、交互与页面结构使用当前技术栈能直接运行的实现。
- 页面只通过已评审 API 读取和修改业务数据；换乘计数、历史日期/时刻衔接与排序由服务端提供，前端不复制一套业务推导。本地后端 API 不等于外部实时票务接口。
- 底图的高德 JS API 2.0 按供应方要求提供浏览器配置。普通地点使用高德 Web 服务 v3，经项目后端查询，服务端密钥走环境变量。铁路时刻、日历和关联轨迹使用需求 §6.1 的固定 GTFS 包，部署账号权限及配额按实际环境核对。
- 地图点选、AI、恢复行程及车次选择共用 [模块与单一 store 约定](../../handoff/20261116-22-frontend.md#modules)；原生模块、请求标识、局部更新、版本保存的最小形状已给出，不另建组件私有行程或事件总线。
- API 错误按 §9.1 进入相应组件状态。绘制、命中和标签能力见 §6。
- 服务端最小字段与写入能力见 [服务契约输入](../../handoff/20261116-22-frontend.md#service-contract)。[合成夹具](fixtures/frontend-cases.json)用于验证前端交互与状态。

### 历史回放主页

历史回放的地图城市与地点搜索共用一个有序行程。起终站和系统换乘站使用规划响应中的实际站点坐标。用户手动选定的站码随行程编辑保留，停留节点显示到站与发站，系统安排的换乘归到对应铁路区间。修改节点、站点、停留天数、日期或换乘间隔后自动重算，失效响应不得更新页面和地图。换乘间隔由用户填写。无路线时保留已匹配前缀和行程输入，标出失败区间。轨迹缺失时保留车次及原因，地图不补画直线。
